WHY DOCKER IS NON-OPTIONAL FOR THIS STACK
⚡ The problem without Docker
After Week 3, FlavorStack has: Express API + Next.js frontend + Redis + MongoDB + BullMQ email worker + BullMQ image worker + BullMQ notification worker + BullMQ loyalty worker + outbox poller. That's 9 processes you need running simultaneously. Without Docker you manually start each one, manage ports, deal with "works on my machine" bugs, and can't deploy cleanly. With Docker Compose — one command: docker compose up.
EVERY DOCKER FILE YOU NEED — WHAT & WHERE
📄 server/Dockerfile Builds the Express API image. Multi-stage: build stage compiles TypeScript → production stage runs compiled JS only. No dev dependencies in prod image.
📄 server/Dockerfile.worker Separate image for BullMQ workers. Same codebase as API but different entrypoint (worker/index.ts not server/index.ts). Lets you scale workers independently from API.
📄 my-app/Dockerfile Builds Next.js frontend. Multi-stage: install → build → standalone output. Uses Next.js standalone output mode for minimal image size.
📄 docker-compose.yml The main file. Defines all services, networks, volumes, env vars, health checks, and dependencies. This is what you run in production.
📄 docker-compose.dev.yml Development override. Mounts source code as volumes (hot reload), skips build steps, exposes debug ports, uses dev env vars. Run with: docker compose -f docker-compose.yml -f docker-compose.dev.yml up
📄 .dockerignore (×3) One per app (server/, my-app/, root). Excludes: node_modules, .env files, .git, dist/, .next/, test files. Keeps images small and secure.
📄 .github/workflows/deploy.yml GitHub Actions CI/CD pipeline. Triggers on push to main: lint → TypeScript check → build Docker images → push to registry → deploy. Simple but production-grade.
📄 nginx/nginx.conf Nginx config as a file (not inline in compose). Handles upstream API routing, WebSocket proxy for Socket.io, static asset caching, SSL termination config.
📄 .env.example Template for all required env vars. Committed to git. Actual .env files never committed. Docker Compose reads from .env automatically.
